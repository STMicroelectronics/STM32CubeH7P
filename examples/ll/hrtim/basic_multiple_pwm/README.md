# __Example: *ll_hrtim_basic_multiple_pwm*__

**Example version:** 2.0.0

[![User Manual](doc/read_the-UM.svg)](https://dev.st.com/stm32cube-docs/examples/arch-v1/en/index.html "An offline version is also available in the STM32Cube firmware package.")

How to configure the HRTIM peripheral in continuous mode to generate PWM waveforms on multiple outputs.
The PWM waveforms generated by the HRTIM output channels can be displayed using an oscilloscope.


## __1. Detailed scenario__

__Initialization phase__: At main program start, the `mx_system_init()` function is called. It initializes the peripherals, nonvolatile memory (such as flash memory, NVM, or external memories), MPU regions (if applicable), the system clock, and the SysTick.

The application executes the following __example steps__:

__Step 1__: Initializes the input clock, counter clock, and output clock of the HRTIM timer. Sets the output channels to 33 kHz on CHx1/CHx2 and 100 kHz on CHy1/CHy2 with the configured duty cycle, then configures the GPIO pins.

__Step 2__: Starts the timer PWM generation on the HRTIM outputs.

__End of example__: If no error occurs, the PWM signal is generated indefinitely.


## __2. Example configuration__

[![Configuration Manual](doc/configure_with-ConfigurationMa.svg)](https://dev.st.com/stm32cube-docs/examples/arch-v1/en/configure/config_toc.html "An offline version is also available in the STM32Cube firmware package.")

### __2.1. Timer configuration__

The *HRTIM* is configured as follows:

- The HRTIM timer is configured in continuous (free-running) and up counting modes.
- The HRTIM timer prescaler, period and compare unit are configured to generate a 33 kHz PWM signal with 25% duty cycle on channel CHx1/2, and a 100 Khz PWM signal with 25% duty cycle on channel CHy1/2 .
- For the HRTIM output channel, the output active level is HIGH. The PWM duty cycle is configured through counter set and reset events.

Note that the HRTIM timer configuration depends on the HRTIM peripheral input clock, which is derived from the system clock tree.
So, it is required to define the system clock configuration and to determine the HRTIM timer input clock before defining the HRTIM timer and output channel configuration.

The system clock configuration is specific to each STM32 MCU (see section [Hardware environment and setup](#3-hardware-environment-and-setup)).

### __2.2. GPIO configuration__

The GPIO pin is configured in:

- Alternate function as a HRTIM output channel of its respective timer instance.
- Push-pull mode with no pull-up or pull-down resistors activated.

In this configuration:

- The sys_clk is set to 520 MHz.
- The HRTIM1 kernel clock is fed directly by sys_clk. The BMPRE prescaler (set to 2) applies only to the AHB/APB bus matrix, not to the HRTIM, so fHRTIM = 520 MHz.
- fHRTIM: set to 520MHz.
- fHRCK: set to 520MHz (prescaler = 1).

For the Timerx, the prescaler is set to 1 so the fTIM = 520 MHz.
To get a 33 kHz PWM signal with a 520 MHz input clock, the period is calculated as:
PER = fTIM / fPWM = 520 MHz / 33 kHz = 15760

The HRTIM compare register values (TIMx_CMPy) used as compare thresholds are obtained by multiplying the period by a fraction of the period (PER x ratio), as shown below:

`TIMx_CMP1 = (TIMx_PERIOD / 4) = (15760 / 4) = 3940`
`TIMx_CMP2 = (TIMx_PERIOD / 2) = (15760 / 2) = 7880`
`TIMx_CMP3 = (3 * TIMx_PERIOD / 4) = (3 * 15760) / 4 = 11820`

The PWM waveform is elaborated in the set/reset crossbar events on the HRTIM output channel:
HRTIM1_CHx1: set on TIMx period (TIMx_PERIOD), reset on TIMx compare unit1 (TIMx_CMP1).
HRTIM1_CHx2: set on TIMx compare unit1 (TIMx_CMP2), reset on TIMx compare unit1 (TIMx_CMP3).

For the Timery, the prescaler is set to 1.
To get a 100 kHz PWM signal with a 520 MHz input clock, the period is calculated as:
PER = fTIM / fPWM = 520 MHz / 100 kHz = 5200

The duty cycle is obtained by multiplying the period by the duty cycle: PER x DC. The resulting numbers are HRTIM compare register values (TIMy_CMPy) used as compare thresholds:

`TIMy_CMP1 = (TIMy_PERIOD / 4) = (5200 / 4) = 1300`
`TIMy_CMP2 = (3 * TIMy_PERIOD) / 4 = (3 * 5200) / 4 = 3900`

The PWM waveform is elaborated in the set/reset crossbar events on the HRTIM output channel:
HRTIM1_CHy1: set on TIMy period (TIMy_PERIOD), reset on TIMy compare unit1 (TIMy_CMP1).
HRTIM1_CHy2: set on TIMy compare unit1 (TIMy_CMP2), reset on TIMy period (TIMy_PERIOD).

## __4. Troubleshooting__

[![Troubleshooting](doc/debug_with-Troubleshooting.svg)](https://dev.st.com/stm32cube-docs/examples/arch-v1/en/debug/debug_toc.html "An offline version is also available in the STM32Cube firmware package.")

Here are the points of attention for this specific example:

__System clock__:

- To provide the high resolution, the HRTIM must be fed directly by the PLL high-frequency output.
- The HRTIM clock depends on the system clock configuration. Changing the CPU clock or the peripheral bus' clock affects the PWM frequency and duty cycle.

__GPIO slew rate__:

The GPIO slew rate is an important parameter that affects the performance of high-frequency signals. Refer to the AN4899 application note in case of issues.
