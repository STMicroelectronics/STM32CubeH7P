Example: mx25lm51245g_read_write

Example version: 2.0.0

How to use the MX25LM51245G OCTOSPI memory using erase/read/write APIs. This example illustrates the process of writing, reading, and erasing data from the OCTOSPI memory.

1. Detailed scenario

Initialization phase: At main program start, the mx_system_init() function is called. It initializes the peripherals, nonvolatile memory (such as flash memory, NVM, or external memories), MPU regions (if applicable), the system clock, and the SysTick.

Step 1: Initializes the MX25LM51245G part.

Step 2: Erases blocks from the external memory. Then writes a data buffer to the same area, in indirect mode, using Octal interface and Double transfer rate.

Step 3: Reads the same data buffer from the external memory, and checks that it matches the buffer written in step 2.

Step 4: Deinitializes the MX25LM51245G part.

End of example: After step 4, the example is completed. You can verify that the example runs properly via the status LED and the ExecStatus variable.

If you enable USE_TRACE, you can follow these execution steps in the terminal logs:

[INFO] Step 1: Device initialization COMPLETED.
[INFO] Step 2: Data buffer written to the external memory (OPI-DTR - Indirect mode).
[INFO] Step 3: Data buffer read from the external memory and matching the initial value.
[INFO] Step 4: Device de-initialization.

2. Example configuration

XSPI: The XSPI is configured with these specific parameters:

  • The memory type is set to “HAL_XSPI_MEMTYPE_MACRONIX.”
  • The CS boundary is set to “HAL_XSPI_BONDARY_NONE.”
  • The memory mode is set to “HAL_XSPI_SINGLE_MODE.”
  • The memory wrap size is set to “HAL_XSPI_WRAP_NOT_SUPPORTED.”
  • The timing state is set to “HAL_XSPI_DLYB_ON.”
  • The chip select release time cycle and the refresh time cycle are set to 0.
