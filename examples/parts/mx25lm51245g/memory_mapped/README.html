Example: mx25lm51245g_memory_mapped

Example version: 2.0.0

How to use the MX25LM51245G OCTOSPI memory using “memory mapped” APIs. This example demonstrates the process of erasing the memory pages to be programmed by sectors. It covers writing using OPI mode with double transfer and reading from the flash memory using memory mapped mode (direct mode).

1. Detailed scenario

Initialization phase: At main program start, the mx_system_init() function is called. It initializes the peripherals, nonvolatile memory (such as flash memory, NVM, or external memories), MPU regions (if applicable), the system clock, and the SysTick.

The application executes the following example steps:

Step 1: Initialize the MX25LM51245G parts driver and configure it in OPI DTR mode.

Step 2: Erases the external memory, in indirect mode, using OPI mode with double transfer.

Step 3: Writes a data buffer to the external memory, using OPI mode with double transfer.

Step 4: Reads the same data buffer from the external memory using memory mapped mode, and checks that it matches the buffer written in step 3.

Step 5: De-initializes the MX25LM51245G part.

End of example: After step 5, the example is completed. You can verify that the example runs properly via the status LED and the ExecStatus variable.

If you enable USE_TRACE, you can follow these execution steps in the terminal logs:

[INFO] Step 1: Device initialization COMPLETED.
[INFO] Step 2: Memory erased (OPI DTR - Indirect mode).
[INFO] Step 3: Data buffer written to the external memory (OPI DTR - Indirect mode).
[INFO] Step 4: Data buffer read from the external memory (MMP - direct mode).
[INFO] Step 4: Data buffer read from the external memory and matching the initial value.
[INFO] Step 5: Device de-initialization.

2. Example configuration

XSPI: The XSPI is configured with these specific parameters:

  • The memory type is set to “HAL_XSPI_MEMTYPE_MACRONIX.”
  • The CS boundary is set to “HAL_XSPI_BONDARY_NONE.”
  • The memory mode is set to “HAL_XSPI_SINGLE_MODE.”
  • The memory wrap size is set to “HAL_XSPI_WRAP_NOT_SUPPORTED.”
  • The timing state is set to “HAL_XSPI_DLYB_ON.”
  • The chip select release time cycle and the refresh time cycle are set to 0.
  • Size bit set to “HAL_XSPI_MEMORY_SIZE_512MBIT”

4. Troubleshooting

Here are the points of attention for this specific example:

Data layout: The read/write start address should be aligned according to the memory address size. In this example, a 4-byte address size is used. Due to the memory organization being split into sectors, blocks, or banks, you need to define the buffer size and start address according to the memory layout.
