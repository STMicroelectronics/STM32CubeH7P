Example: hal_hrtim_basic_single_pwm

Example version: 2.0.0

How to configure the HRTIM peripheral in continuous mode to generate a 100 kHz PWM signal with a 50% duty cycle. The PWM waveform generated by the HRTIM output channel can be displayed using an oscilloscope.

1. Detailed scenario

This scenario demonstrates how to configure a HRTIM to generate a basic PWM signal.

Initialization phase: At main program start, the mx_system_init() function is called. It initializes the peripherals, nonvolatile memory (such as flash memory, NVM, or external memories), MPU regions (if applicable), the system clock, and the SysTick.

The application executes the following example steps:

Step 1: Initializes the input clock, counter clock, and output clock of the HRTIM timer. Sets the duty cycle of the output channel and the GPIO pin.

Step 2: Starts the timer PWM generation on the HRTIM output.

End of example: If no error occurs, the PWM signal is generated indefinitely.

2. Example configuration

2.1. Timer configuration

The HRTIM is configured as follows:

  • The HRTIM timer is configured in continuous (free-running) and up counting modes.
  • The HRTIM timer prescaler, period and compare unit are configured to generate a 100 kHz PWM signal.
  • For the HRTIM output channel, the output active level is HIGH. The PWM 50% duty cycle is configured through counter set and reset events.

Note that the HRTIM timer configuration depends on the HRTIM peripheral input clock, which is derived from the system clock tree. So, it is required to define the system clock configuration and to determine the HRTIM timer input clock before defining the HRTIM timer and output channel configuration.

The system clock configuration is specific to each STM32 MCU (see section Hardware environment and setup).

2.2. GPIO configuration

One pins must be configured for the PWM signal: see the specific boards setups

The GPIO pin is configured in:

  • Alternate function as a HRTIM output channel of its respective timer instance.
  • Push-pull mode with no pull-up or pull-down resistors activated.

3. Hardware environment and setup

3.1. Generic Setup

The PWM signal generated by the timer channel can be displayed by connecting an oscilloscope to the corresponding board connector.

3.2. Specific board setups

On STM32H7P series.
Common configuration.

To provide the high resolution, the HRTIM must be fed directly by the PLL high-frequency output.

Each timer in the HRTIM has its own individual clock prescaler, which is used to adjust the timer high-resolution clock fHRCK.

Standard STM32H7Pxx HRTIM clock distribution diagram:

In this configuration:

  • The sys_clk is set to 520 MHz.
  • The CPRE prescaler is set to 1 so the fHRTIM = 520 MHz.
  • fHRTIM: set to 520MHz.
  • fHRCK: set to 260MHz (prescaler = 2).

To get a 100 kHz PWM signal with a 260 MHz input clock, the period is calculated as: PER = fHRCK / fPWM = 260 MHz / 100 kHz = 2600

The 50% duty cycle is obtained by multiplying the period by the duty cycle: PER x DC to set the compare value: Here PER * DC = 2600 * 0.5 = 1300

The PWM waveform is elaborated in the set/reset crossbar events on the HRTIM output channel: HRTIM1_CHB2: set on TIMB period (TIMB_PERIOD), reset on TIMB compare unit1 (TIMB_CMP1).

4. Troubleshooting

Here are the points of attention for this specific example:

System clock:

  • To provide the high resolution, the HRTIM must be fed directly by the PLL high-frequency output.
  • The HRTIM clock depends on the system clock configuration. Changing the CPU clock or the peripheral bus’ clock affects the PWM frequency and duty cycle.

GPIO slew rate:

The GPIO slew rate is an important parameter that affects the performance of high-frequency signals. Refer to the AN4899 application note in case of issues.
